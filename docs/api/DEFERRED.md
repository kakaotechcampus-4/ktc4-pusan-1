# 나중에 정해도 되는 것

FE 가 **기본값을 정하고 이미 진행한** 항목입니다. 확정되면 "고칠 곳" 한 군데만 수정하면 됩니다.
지금 회의에서 다룰 필요가 없습니다.

| # | 항목 | FE 가 택한 기본값 | 고칠 곳 |
| --- | --- | --- | --- |
| 1 | 에러 응답 본문 | HTTP status 로만 분기 | `api/interview.ts` 의 `FAILURE_BY_CODE` 에 줄 추가 |
| 2 | 정원 초과 구분 | 409 를 "이미 종료" 와 합쳐 한 문구로 안내 | 위와 같음 + `JoinFailure` 에 항목 추가 |
| 3 | 토큰 TTL | 재발급 로직 없음. 만료되면 새로고침 | `useInterviewRoom` 의 `Disconnected` 핸들러 |
| 4 | join 재호출 시 동일인 인식 | FE 는 그냥 재호출한다 | 서버 몫. FE 변경 없음 |
| 5 | `start` 호출 주체 | 아직 호출하지 않음 | 면접관 화면이 생길 때 결정 |
| 6 | 녹화(Egress) 제어 | FE 관여 없음 | 서버 몫. FE 변경 없음 |
| 7 | 지원자 이름 | 표시하지 않음 | 응답에 필드가 생기면 `InterviewRoomView` 에 전달 |
| 8 | `reviewStatus` · 면접 기록(S3) | 이번 스코프 밖 | 별도 이슈 |
| 9 | `inviteUrl` 도메인 (`https://irya.com` 고정) | 로컬은 `/interview/{sessionId}` 를 직접 입력해 테스트 | 서버가 환경별로 주입 |
| 10 | 면접 생성 시 `interviewerId` 위조 가능 | 인증 도입 시 함께 해결 | `api/client.ts` 의 Authorization 헤더 |

## 1·2번 상세

명세가 `409` 하나에 "이미 종료된 Session" 과 "정원 초과" 를 함께 씁니다.
지금 FE 는 두 경우를 합쳐 이렇게 안내합니다.

> 지금은 입장할 수 없습니다. 이미 종료되었거나 정원이 찼습니다.

서버가 `error.code` 를 주기 시작하면 아래처럼 한 줄씩만 넣으면 두 문구로 갈립니다.

```ts
const FAILURE_BY_CODE: Record<string, JoinFailure> = {
  SESSION_ENDED: 'ended',
  ROOM_FULL: 'full',
};
```

# 지금 정해야 하는 것

아래 4개는 기본값으로 넘길 수 없거나, 넘기면 나중에 되돌려야 합니다.

| # | 항목 | 왜 지금인가 | 담당 |
| --- | --- | --- | --- |
| A | **지원자 화면 설계** | 면접관 전용 패널(전사·추천 질문·종료)을 지원자에게 뭘로 대체할지 정해지지 않았습니다. 그리는 화면 자체가 없어 FE 작업이 실제로 막힙니다 | 팀 (BE 무관) |
| B | **면접관 입장 경로** | `inviteUrl` 은 지원자용입니다. 면접관도 `/interview/:sessionId` 로 들어오나요? | BE |
| C | **전사·추천 질문 WebSocket** | 명세 8개 어디에도 경로가 없습니다. 없으면 두 패널이 영구히 목 데이터입니다. BE 담당인지 AI 담당인지도 미정입니다 | BE · AI |
| D | **`role` 을 클라이언트가 선언하는 구조** | 지원자가 `{"role":"INTERVIEWER"}` 를 보내면 면접관 토큰을 받습니다. 인증 없이도 역할별 링크 2개 발급으로 해결됩니다 | BE |

D 는 FE 수정 비용이 작습니다(`joinSession` 호출부 한 곳). 다만 **데모에서 실제로 드러날 수 있어** 우선순위가 높습니다.
