# 실제 업무 흐름 검증 — 2026-10-30

현재 라이트 디자인과 실제 API를 사용한 로컬 통합 검증이다. 설계 시안이나 가로챈 HTTP 성공 응답을 증거로 사용하지 않았다.

## 환경·검증 경계

- FE: develop `897ebf8`에서 시작한 기능 스택. BE: 미병합 #252 + 소유자·목록 조회 + reason. AI: 미병합 #250 + #251 + REPORT 폴러.

- 사용자 허용에 따라 STT·검토·질문 생성은 고정 입력으로 대체했다. 리포트는 실제 REPORT 폴러와 추출형 ReportAgent를 실행했다. 외부 모델의 품질·속도·비용은 미검증이다.
- canvas/AudioContext 인공 트랙을 실제 두 참가자의 LiveKit으로 송수신했다. 물리적인 기기·권한 프롬프트·장치 분리·외부 네트워크는 미검증이다.
- Egress·오브젝트 저장소가 없어 실제 녹화 파일 생성·병합은 미검증이다. 녹화 없음·처리 중·실패의 API 표시를 구분했다.
- 최초 흐름 검증 이후 아래 통합 브랜치에서 #253·#254도 합쳐 재검증했다. 동의 #255/#256의 계약 선택과 삭제 #246은 대기다. 제품 전체·운영 배포 완료를 의미하지 않는다.

## 확인한 흐름

1. 두 참가자 접속 → 실제 시작 API → INTERVIEWING.
2. 내 마이크·카메라 끄기와 복구를 상대 publication 상태로 확인. 상대 소리는 로컬 재생만 끄고 마이크 송신과 독립적이었다.
3. 고정 발화 4건을 실제 내부 WS로 보내 ACK를 받고 LiveKit 자막으로 표시. 질문 7건을 실제 저장·패킷 경로로 보내 최신 5개 표시 확인.
4. 면접 중 메모 작성 → 실제 PATCH → 종료·재진입 후 보존.
5. 실제 종료 API → ENDED. 지원자가 대기 화면에 남던 문제를 수정하고 새 세션에서 지원자 화면도 종료됨을 확인.
6. 고정 검토 결과를 실제 내부 API에 저장 → 공개 검토 조회 → 항목 포함 → 검토 완료 → 리포트 POST → PROCESSING → 실제 폴러 생성·PUT → READY.
7. 같은 면접의 검토·리포트·목록에서 CONFIRMED·READY·메모 일치. 두 명 비교와 직접 리포트 URL 확인.
8. 실제 XLSX 버튼의 Blob/ZIP에서 선택한 2건·4개 시트·면접 ID·한글 메모·수식 비실행 확인. 입력 직후 CSV도 최신 메모를 담도록 저장 대기·재조회를 수정하고 확인.
9. 375×812 모바일·1366×768 노트북·1680×1120 확인. 모바일 문서 가로 넘침 없이 표 내부 가로 스크롤 사용. 질문 토글 꺼짐·켜짐 캡처.
10. 전용 DB에 예시 면접 1,000건 추가. 실제 브라우저 검색 → 50행 선택 → 검색 결과 1,000건 선택 → 정렬 → 다음 페이지에서도 50행 체크·선택 유지(2/20페이지). 목록 HTTP 1회(한 번의 로컬 측정 약 23ms), 행별 상세 HTTP 0회. BE는 1건/1,000건 모두 본조회 1회 + 보조 조회 6회. 운영 성능 보장은 아니다.

## 증거·재검증

JSON은 실제 송수신 상태, 고정 입력 경계, 종료·메모 보존, 최종 저장 일치, 1,000건 선택·요청 수를 기록한다. PNG는 실제 렌더링한 예시 자료다. `sha256.json`은 파일 해시다. 토큰·키·개인 자료는 포함하지 않았다.

Vite에서 `tests/browser/room.html?sessionId=<로컬 테스트 세션>&role=INTERVIEWER`와 CANDIDATE를 열면 현재 통화 훅·화면에 인공 트랙을 공급한다. API·WS·LiveKit은 대체하지 않는다. 정상 로컬 테스트 계정과 준비된 세션을 사용한다. QA 진입점은 production 빌드 입력에 포함되지 않는다.

브라우저 검증은 `gstack-browse-safe`를 사용하고 `stop` 다음 `check`로 종료·디스크·덤프 상태를 확인한다.
